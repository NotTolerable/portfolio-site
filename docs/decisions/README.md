Use a numbered record such as `0001-site-framework.md` for a significant technical decision. Keep records concise:

```markdown
# NNNN: Decision title

Status: proposed | accepted | superseded
Date: YYYY-MM-DD

## Context
The requirement or constraint driving this choice.

## Decision
The chosen approach and its scope.

## Alternatives considered
Credible alternatives and why they were not selected.

## Consequences
Benefits, costs, limitations, and follow-up work.
```

Mark a decision accepted only after it has actually been agreed. When a decision changes, preserve its history, mark it superseded, and link to the replacement record. Update the architecture document to describe the current design.
